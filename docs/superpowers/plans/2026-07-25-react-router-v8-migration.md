# react-router v8 Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move the frontend off the removed `react-router-dom` package onto
`react-router@^8.3.0` so `npm audit --omit=dev --audit-level=high` exits clean
(GHSA-qwww-vcr4-c8h2, issue #562).

**Architecture:** Pure package migration. `react-router-dom` was deleted in
React Router v8; every API prumo uses now lives on the `react-router` root
export. Declarative routing (`<BrowserRouter>` in `frontend/App.tsx`) is
unchanged — only import specifiers move. No data-router migration, no
`react-router/dom` imports (that entry point serves `RouterProvider` and
`HydratedRouter`, neither of which prumo uses).

**Tech Stack:** TypeScript strict, React 19, Vite 8, Vitest 4, Playwright,
eslint flat config, React Compiler (`panicThreshold: 'all_errors'`).

**Spec:** `docs/superpowers/specs/2026-07-25-react-router-v8-migration-design.md`

## Global Constraints

- All frontend commands run from the **repo root**. There is no
  `frontend/package.json`. Never `cd frontend && npm ...`.
- Use `npm run test:run` (vitest run). Never bare `npm test` — that is watch
  mode and hangs agent sessions.
- The CI typecheck gate is `npx tsc -p tsconfig.app.json --noEmit`. Vitest
  passing is **not** a typecheck.
- React Compiler runs at `panicThreshold: 'all_errors'`: a component or hook it
  cannot compile fails the build **and** vitest.
- Target version is exactly `react-router@^8.3.0`. `8.3.0` is the first patched
  release (advisory range `>= 7.12.0, < 8.3.0`).
- **Never run `npm audit fix --force`** here — it downgrades to
  `react-router-dom@7.11.0`, which is behind the fix, not ahead of it.
- English only for code, comments, and commit messages.
- Do **not** edit `react-router-dom` mentions under `docs/superpowers/plans/`.
  Those are point-in-time plan snapshots; rewriting them falsifies the record.
- Do not promote to `main` in this pass. `dev` only.

## Task 1: Swap the package and rewrite every import

The dependency swap and the import rewrite **must land in one commit**.
Uninstalling `react-router-dom` while imports still reference it leaves a tree
that does not typecheck; rewriting imports first while the package is still
declared leaves a phantom dependency. Neither intermediate state should be
committed.

**Files:**

- Modify: `package.json` (line 85)
- Modify: `package-lock.json` (regenerated)
- Modify: all 43 frontend files listed above

**Interfaces:**

- Consumes: nothing from earlier tasks.
- Produces: `react-router` as the only router package. Every downstream import
  is `from "react-router"`. Named exports used across the tree are
  `BrowserRouter`, `MemoryRouter`, `Routes`, `Route`, `Link`, `Navigate`,
  `Outlet`, `useNavigate`, `useParams`, `useLocation`, `useSearchParams` — all
  present on the `react-router` v8 root export.

- [ ] **Step 1: Capture the RED state — the audit currently fails**

```bash
npm audit --omit=dev --audit-level=high
```

Expected: non-zero exit, reporting
`react-router 7.12.0 - 8.2.0 ... GHSA-qwww-vcr4-c8h2` and
`2 high severity vulnerabilities`.

Save the exit code as proof the gate is red before the change:

```bash
npm audit --omit=dev --audit-level=high > /tmp/audit-before.txt 2>&1; echo "EXIT: $?"
```

Do not pipe this into `tail`/`head` — a pipe makes `$?` the exit code of the
last pipeline stage, not of `npm audit`.

- [ ] **Step 2: Swap the dependency**

**Worktree note — read before running.** This worktree has no `node_modules` of
its own; Node currently resolves packages up to the parent checkout at
`/Users/raphael/PycharmProjects/prumo/node_modules`. The command below is
therefore a *full* first install into the worktree (expect 1–3 minutes and a
new gitignored `node_modules/` here). That is desired: it isolates this branch's
dependency tree from the parent checkout, which stays on `react-router-dom`.

```bash
npm uninstall react-router-dom && npm install react-router@^8.3.0
```

Expected: `package.json` now lists `"react-router": "^8.3.0"` and no longer
lists `react-router-dom`.

Confirm the worktree now resolves its own copy, not the parent's:

```bash
node -e "console.log(require.resolve('react-router', {paths:[process.cwd()]}))"
```

Expected: a path **under this worktree**, not under
`/Users/raphael/PycharmProjects/prumo/node_modules`.

- [ ] **Step 3: Verify the declared dependency**

```bash
node -e "const p=require('./package.json'); console.log('react-router:', p.dependencies['react-router']); console.log('react-router-dom:', p.dependencies['react-router-dom'] ?? '(absent — correct)')"
```

Expected:

```text

react-router-dom: (absent — correct)
```

- [ ] **Step 4: Rewrite all 43 import specifiers**

`react-router-dom` is a strict superstring of `react-router`, and no other
`react-router*` package name appears anywhere in `frontend/`, so a literal
substring replace is safe. Scope it to `frontend/` so no doc is touched.

```bash
grep -rl "react-router-dom" --include="*.ts" --include="*.tsx" frontend/ \
  | xargs sed -i '' "s|react-router-dom|react-router|g"
```

(`sed -i ''` is the macOS/BSD form. On GNU sed use `sed -i`.)

- [ ] **Step 5: Verify the rewrite is complete and correct**

```bash
echo "remaining react-router-dom in frontend: $(grep -rc 'react-router-dom' --include='*.ts' --include='*.tsx' frontend/ | grep -v ':0' | wc -l | tr -d ' ')"
echo "react-router imports now: $(grep -rho 'from ["'"'"']react-router["'"'"']' --include='*.ts' --include='*.tsx' frontend/ | wc -l | tr -d ' ')"
```

Expected:

```text

react-router imports now: 43
```

Also confirm nothing needs `react-router/dom` — we use neither
`RouterProvider` nor `HydratedRouter`:

```bash
grep -rn "RouterProvider\|HydratedRouter" --include="*.ts" --include="*.tsx" frontend/ || echo "(none — correct, no react-router/dom import needed)"
```

Expected: `(none — correct, no react-router/dom import needed)`

## Task 2: Guard against `react-router-dom` returning

Removing the package already makes a stale import fail `tsc`, but the failure
reads as a bare module-not-found. A named lint error explains *why* the package
is gone and what to use instead.

**Files:**

- Modify: `eslint.config.js` (the `rules` block of the main
  `**/*.{ts,tsx}` config object)

**Interfaces:**

- Consumes: Task 1's fully-rewritten tree (the rule must not fire on real code).
- Produces: an eslint error on any future `react-router-dom` import.

- [ ] **Step 1: Write the failing test — a deliberate violation**

Create a temporary file that the rule must reject:

```bash
cat > frontend/__lint_probe__.ts <<'EOF'
// Temporary lint probe — deleted in Step 5.
import {Link} from "react-router-dom";
export const probe = Link;
EOF
```

- [ ] **Step 2: Run lint to verify it currently does NOT fail (RED)**

```bash
npx eslint frontend/__lint_probe__.ts; echo "EXIT: $?"
```

Expected: `EXIT: 0` — no rule exists yet, so the banned import passes. This
proves the guard is genuinely absent rather than accidentally already present.

- [ ] **Step 3: Add the guard**

In `eslint.config.js`, inside the `rules` object of the first config block
(the one with `files: ["**/*.{ts,tsx}"]`), add after the `"prefer-const"` line:

```js
      // react-router-dom was removed in React Router v8. Uninstalling it
      // already breaks a stale import at tsc, but that surfaces as a bare
      // module-not-found; this names the reason. See #562 /
      // GHSA-qwww-vcr4-c8h2.
      "no-restricted-imports": ["error", {
        paths: [{
          name: "react-router-dom",
          message: "react-router-dom was removed in React Router v8. Import from 'react-router' instead (or 'react-router/dom' for RouterProvider/HydratedRouter).",
        }],
      }],
```

- [ ] **Step 4: Run lint to verify the guard fires (GREEN)**

```bash
npx eslint frontend/__lint_probe__.ts; echo "EXIT: $?"
```

Expected: `EXIT: 1`, with the custom message quoted above.

If it still exits 0, `tseslint.configs.recommended` has disabled the base rule
in this setup. In that case replace the key `"no-restricted-imports"` with
`"@typescript-eslint/no-restricted-imports"`, keeping the options identical,
and re-run this step. Do not proceed until the probe fails.

- [ ] **Step 5: Delete the probe**

```bash
rm frontend/__lint_probe__.ts
```

- [ ] **Step 6: Verify the real tree is clean**

```bash
npm run lint; echo "EXIT: $?"
```

Expected: `EXIT: 0`. Warnings are acceptable (the repo has pre-existing
`@typescript-eslint/no-unused-vars` warnings); errors are not.

- [ ] **Step 7: Confirm the probe is gone before committing**

```bash
test ! -e frontend/__lint_probe__.ts && echo "probe removed — OK"
git status --short
```

Expected: `probe removed — OK`, and `git status` shows only
`eslint.config.js` modified.

- [ ] **Step 8: Commit**

```bash
git add eslint.config.js
git commit -m "chore(lint): ban react-router-dom imports (#562)

Names the reason the package is gone instead of leaving a future
regression to surface as a bare module-not-found.

Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>"
```

## Task 3: End-to-end verification and PR

Routing is exercised end-to-end, so E2E carries the real weight here. Unit
tests mount `MemoryRouter` harnesses and will not catch a real navigation
regression.

**Files:** none modified. This task produces evidence.

**Interfaces:**

- Consumes: Tasks 1 and 2, committed.
- Produces: pasted command output proving each gate, and a PR against `dev`.

- [ ] **Step 1: Start the local stack**

Local Supabase is already running (ports 54321/54322). `make start` is
idempotent and non-destructive: it skips Supabase if up, applies only
auth/storage migrations via `supabase db push --local`, and skips backend and
frontend if their ports already respond. **Do not run `make db-fresh` or
`make reset-db`** — the user explicitly declined a database wipe.

Run it from this worktree (`FRONTEND_DIR := .`, so the dev server serves this
branch's code):

```bash
make start
```

**Port-8080 trap — this can silently invalidate the entire E2E run.**
`frontend-start` skips if anything is already listening on 8080. If the parent
checkout's dev server is running, Playwright would test the *parent's*
`react-router-dom` code and pass while proving nothing. Assert the serving
process is this worktree's:

```bash
pid=$(lsof -ti:8080 | head -1); echo "pid=$pid"; lsof -a -p "$pid" -d cwd -Fn | grep '^n'
```

Expected: the printed cwd is
`/Users/raphael/PycharmProjects/prumo/.claude/worktrees/zettlr-bibtex-citations-fc0a85`.

from here before continuing.

- [ ] **Step 2: Run the local E2E suite**


Expected: PASS across the `local-api`, `local-ui`, and `local-hitl` projects.

database and can race. A failure in `qa-consensus-ai-trace` or

attributing any failure to the migration, re-run that spec alone:


If it passes in isolation, it is the known race, not a routing regression —
record that and move on.

If fixtures fail for missing seed data, **stop and report**. Do not wipe the
database to make them pass.

import. The Task 2 lint guard is independent and harmless on its own, but
revert it too if Task 1 is reverted, or `npm run lint` will pass while nothing
imports the banned package.
