# Guided setup prompts, inline read-only Apps and a chat eval suite for the MCP server Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a researcher using prumo from a chat host gets three guided-setup prompts (review question, extraction form, draft review), sees a project's questionnaire draft and its AI runs as inline read-only cards (MCP Apps) where the host supports them, and the team can measure the chat experience with an opt-in eval suite run against a local `/mcp`. Nothing here adds a write, a migration or a REST change; hosts without Apps get the same text and `structuredContent` as today.

**Architecture:** prompts register through the shipped `agent_prompt` helper (`api/mcp/prompts.py`) and are filtered by the existing `_has_scope`/`_PROMPT_SCOPES` predicate, so `server.py`'s prompt code is untouched. Apps use the SDK's `mcp.server.apps.Apps` extension: a new package `api/mcp/apps/` builds one `Apps()` instance, registers two static `ui://` HTML resources at import (no import of `server`), and `server.py` passes it as `extensions=[apps]`; `agent_tool(ui_resource=…)` stamps `_meta.ui.resourceUri` and refuses an unregistered URI at registration. The eval harness lives in `backend/scripts/mcp_chat_eval/` (outside the app layers, like `citation_eval` and `parsing_bakeoff`); Claude is driven through `pydantic-ai`'s Anthropic model, and the runner bridges the `mcp` client's tools into pydantic-ai tools (pydantic-ai's own MCP toolset does not import against `mcp` 2.2).

**Tech Stack:** FastAPI, Pydantic v2, MCP Python SDK 2.2 (`MCPServer`, `mcp.server.apps`, `mcp.Client`), static HTML + vanilla JS (no build, no CDN), `pydantic-ai` (`AnthropicModel`, `Tool.from_schema`, `FunctionModel` in tests), pytest.

**Scope:** 5 tasks (6.6, 6.7, 6.8, 6.9a, 6.9b) plus a slice-end review step, one PR. No spec link: the goal, the global constraints and the per-task requirements below are the contract.
